Intel Sustainability Timeline

2025 · Accessibility

An accessible, scroll-snapping timeline of Intel's environmental history, 1968–2024.

A single-page timeline that walks through eleven moments in Intel's sustainability story — from the company's founding through its 2040 net-zero commitment. The brief was less about the content and more about the constraint: build something visually rich that still works completely for someone using a screen reader or navigating by keyboard alone. Every design decision had to survive that test.

What I focused on

  • Semantic structure first. Real <header>, <main>, <section>, and <article> landmarks instead of nested divs, so assistive tech gets a usable document outline.
  • Keyboard-navigable timeline. Each card is focusable, so the whole timeline can be traversed by tabbing — not just by scrolling or dragging.
  • Descriptive alt text on every image, written to convey what the image contributes rather than restating the heading next to it.
  • Labeled form controls using visually-hidden labels, so the newsletter input announces itself properly without cluttering the visual design.
  • ARIA region labeling on the timeline so it's announced as a named landmark, and a responsive Bootstrap grid that reflows cleanly down to mobile.

Built with

  • HTML5
  • CSS3
  • CSS Scroll Snap
  • Bootstrap 5.3
  • Bootstrap Icons
  • WCAG / ARIA

L'Oréal AIdvisor

2025 · AI / Serverless

A conversational beauty assistant that recommends products and builds routines.

A chat interface that answers questions about L'Oréal's makeup, skincare, haircare, and fragrance lines and suggests personalized routines. The interesting problem wasn't the chat UI — it was doing it without ever shipping an API key to the browser. I put a Cloudflare Worker in front of the OpenAI API so the key stays server-side and the front end only ever talks to my own endpoint.

What I focused on

  • Serverless proxy architecture. A Cloudflare Worker holds the OpenAI key as an encrypted secret, handles CORS preflight, forwards the conversation to GPT-4o, and returns the response — the client never sees a credential.
  • Persona through system prompting. A system message scopes the model to L'Oréal products so it stays on-brand instead of answering as a general assistant.
  • Responsive conversation state. A typing indicator appears the moment a message is sent and is replaced in place by the reply, so the interface never looks frozen while the model is generating.
  • Graceful failure. Network and API errors surface as a visible in-chat message rather than a silent dead end, and the chat auto-scrolls to keep the newest message in view.
  • Progressive disclosure. The assistant lives in a collapsible panel that scrolls itself into view when opened, so it enhances the page rather than dominating it.

Built with

  • JavaScript (ES6+)
  • OpenAI GPT-4o
  • Cloudflare Workers
  • Fetch API / async-await
  • REST
  • HTML5
  • CSS3

NASA Space Explorer

2025 · API / Front-end

A gallery that pulls NASA's Astronomy Picture of the Day feed and makes it browsable.

Fetches NASA's APOD feed and renders a random six-entry gallery on demand — each card carrying the image or video, its title, date, and a trimmed explanation you can expand. The wrinkle in the APOD data is that entries aren't uniform: most are images, but some are YouTube videos, so the renderer has to branch on media type and produce a genuinely different card for each rather than breaking on the ones it didn't expect.

What I focused on

  • Media-type branching. Images render as figures; video entries render as embedded, fullscreen-capable iframes with a fallback link to open the source in a new tab.
  • Readable density. Explanations are truncated to a scannable length with a "read more" control that expands the full text in place, so the grid stays browsable.
  • Async data handling. The whole gallery is built from a single fetch with async/await, shuffled server-side-agnostically in the client, and wrapped in error handling that shows a human-readable message instead of an empty page.
  • Responsive CSS grid that reflows from a multi-column gallery down to a single column, with a friendly empty state before the first fetch.
  • Automated deployment via a GitHub Actions workflow that publishes the site to GitHub Pages on every push to main.

Built with

  • JavaScript (ES6+)
  • NASA APOD API
  • Fetch API / async-await
  • JSON
  • CSS Grid
  • GitHub Actions

Digital Recipe Cards

2026 · Front-end

A browsable set of interactive recipe cards.

A digital take on the index-card recipe box — recipes laid out as cards you can flip through, search, and read on a phone while your hands are busy. Built to keep the charm of a physical card while adding the things paper can't do: filtering, scaling, and instant lookup.

What I focused on

  • Card-based layout that keeps a full recipe legible on one screen without scrolling past the ingredients.
  • Interactive states — flip, expand, or filter cards to move between the ingredient list and the method.
  • Mobile-first design, because a recipe is read standing up in a kitchen, not at a desk.
